# DSH Code Review

精简、只读的 Git/SVN 代码审查插件。读取指定变更及显式上下文，复用当前 DSH Agent 的模型，输出有证据和可校验位置的问题。不会自动修复、提交、回滚或发布。

## 当前状态

当前代码版本为 0.23.3

单提交审查直接读取原始commit头的父节点，不受浅克隆遍历边界影响；缺失父树明确失败且不自动fetch，不能把非根提交当空旧侧。

Git历史审查预览传 `commit`（相对唯一父提交，根提交空旧侧；merge需区间），或 `baseRevision` 与 `targetRevision`（精确端点树差异，非merge-base）；两类互斥。预览/报告显示解析对象ID，执行复捕获hash验证引用变化。历史显式/自动直接导入上下文只捕获目标提交树普通blob，默认20总量且排除变更不能再进入；历史显式规则同样只从目标树blob捕获，最多4个md/txt、UTF-8、每个16KiB/合计32KiB，不混工作树，SVN不冒充此语义。

工具对错误行锚可进行一次同文件同侧唯一完整原文纠正，须重叠原引用精确编辑；原候选/状态保留JSON，Markdown提示。纠正后仍校验窗口、跨文件编辑及生成读取证据，不增调用、不猜歧义或跨文件迁移，不证明缺陷或因果。

可在预览传入 `autoContext: true`，显式选择有界Git/SVN直接import/include上下文捕获；默认关闭。候选、阻塞、截断及实际路径在预览可见，正文仅在确认后发送，执行重新验证快照。仅当前侧导航非历史/调用图，SVN使用离线正常节点索引支持同样导航；不会自动引入未跟踪或排除变更。，包含有界覆盖预检、显式项目规则及候选证据与反证复核；发布状态以 npm 和 GitHub Release 为准。已通过真实临时 Git/SVN 仓库测试，以及隔离进程中的真实 DSH ToolRuntime 注册验证。当前开发会话的实际预览已返回0.6.0的plan/rules字段，空变更预览与默认关闭外发已验证；已进行经宿主审批的六次小规模真实试跑，累计12次模型调用；四组合成正负例与历史修复对照符合预期，历史引入方向检出候选但引用复核未完成（partial）。不是独立盲测或整体质量证明。详情见 [试跑结果](evaluation/PILOT-RESULTS.md)。

## 工作区下多个子仓库（0.11.0）

当会话目录不是仓库而其子目录含Git/SVN仓库时，预览可指定 `repositoryPath`，例如会话位于工作区根时传 `{ "repositoryPath": "c3animation" }`。该参数必须是工作区相对路径（正斜杠），指向明确仓库根；不能使用绝对路径、上级路径或链接目录。文件、上下文、规则路径仍相对此次选定仓库。多个子仓库分别预览和执行，不混用快照；execute只接收previewId，不能另改目标。省略参数保持原行为。使用此参数需宿主安装0.11.0或更新版本；仓库发布不会自动更新当前宿主。

## 完整文件权限与审批策略

0.17.0起注册工具沿用DSH正常工具执行权限，不再主动调用approval.request，不要求额外allowModelSending开关。宿主工具权限控制入口调用；完整权限下不再因插件重复审批而失败。不修改宿主策略，不把never解释为allowed-once。

## C++关联与审批诊断（0.16.0）

批准文件中的同目录唯一头/实现命名与字面量引号include进入现有关联分组，最多4文件的综合仍共享原读取/调用/生命周期预算。显式context注释保留from/to与include原行，current内容不冒充old历史。无需扫描新文件或执行编译器；系统include、构建搜索路径、条件宏和不支持文本不解析，同目录命名不证明绑定。

主输入提供每侧最多20条零参独立调用原位置，含 `worker.join()`、`debugger->Close()`、`Allocator::Shutdown()` 等语法导航；标记未解析，不证明宏展开、重载选择、动态分派或执行顺序，也不表示全部调用覆盖。其他源码须批准范围内read获取。线程退出/调试器关闭/分配器生命周期合成缺陷与safe反例仅验证明确抽象契约及离线证据协议，不是编译或真实模型质量成绩。

0.16.x的独立外发审批已在0.17.0移除；仍保留预览确认及快照/范围/只读校验。未执行或失败仍不是审核通过。

## C#显式上下文位置线索（0.15.0）

仅注释已批准.cs context，不增加读取或覆盖。支持file-scoped同namespace、静态class、public static零参void/int/bool/string方法与独立Type.Method()语法；保留调用/类型/方法原始行号。目标括号须平衡、方法直属类型；重载、同名竞争者（包括不支持语法）、局部遮蔽、using/partial/继承或动态等不推定绑定。有字符串/注释/预处理等不支持文本保守不生成线索，不影响普通源码审查。当前context明确不是old历史内容。不执行编译器、工程或用户源码，不冒充C++适配、语义绑定或可达性证明，线索不足仍须模型说明证据限制。

## 批准快照内跨文件综合（0.14.0）

关联组最多4个批准主文件、至少2个文本变化时追加跨文件综合。目录保留完整精确编辑原位置，不作为源码证据；每条发现须引用至少2文件的 `interaction.editRefs:[{fileId,editId}]`，主attribution与主引用一致，原锚重叠主编辑，每个引用编辑至少一非空侧须本综合生成read完整覆盖。共享批准reader/全局调用额度，嵌入组最后主文件原超时，不重置生命周期；预检包含额外初始调用，检索复核另计。interactions独立记录pending/completed/blocked，跨组和未完成明确限制。不合并多文件候选，不自动扩文件/仓库。源码/规则/context仍不可信。真实模型样本未跑，安全反例空输出模拟不代表模型查准率；拒绝审批表示未审查不是通过。

## 静态调用绑定线索（0.13.0）

批准JS/TS源码中的命名相对import及别名、简单独立调用，可补充到同侧直接 `export function` 声明的原始行号线索。组输入 `bindingRelations` 及显式上下文注释保留导入/调用/声明位置；不新增读取、组成员或审查覆盖。局部名其他出现（参数/声明/赋值/逃逸）、目标名额外出现、重复导出、重导出或不支持语法保守不生成绑定线索；绑定不确定不阻止普通源码审查。不是通用模块解析、语义绑定或可达性/因果证明。输入预算不足沿用原有关联回退，不截断规则或上下文。

## 跨窗口综合分析（0.12.0）

主文件需要多批精确窗口时，在局部分析后追加一次有界综合检查。完整原始窗口目录不充当源码；综合发现必须引用至少两个不同窗口的编辑，每个引用编辑至少一个非空旧/新侧必须在本综合生成阶段被批准read完整覆盖（不能借用前批/复核审计或search）。使用原定位及证据复核，不截断规则/context。共享原每文件超时和全局调用/读取额度；预检minimumCalls包含综合初始请求，后续检索复核另计。synthesisStatus独立记录pending/completed/blocked，局部窗口完成不表示综合完成；输入超限或预算耗尽不冒算覆盖。读取覆盖及模型分析仍不证明跨路径正确性或因果事实，真实模型质量未新增验证。

## 修改前后对照复核（0.11.0）

复核可返回 `regression`：`introduced`（模型判断本次引入）、`preexisting`（模型判断原有问题）、`uncertain`（对照不足）。前两者必须引用候选主文件旧新两侧的已精确校验证据，索引指向本候选复核 `evidence` 数组；空源或缺少任一侧时不能虚构支持。旧协议缺省标为 `unassessed`，关闭复核同样明确未评估。报告保留全部候选并展示分类、理由及 `regressionCoverage`；模型支持但对照不足进入限制。分类及引用有效不等于因果事实成立，也不宣称真实模型质量提升已获验证。去重隔离分类/理由/证据索引冲突，uncertain及unassessed不折叠。

## 保守重复报告归组（0.10.0）

结构化报告保留全部原始 `findings`，附加 `findingGroups` 中的零基发现索引。仅当归因引用有效、复核支持、整套精确证据及标题、触发条件、影响、建议、前后行为和解释一致时归组，不按标题相似、证据部分重叠或传递关系合并。Markdown精简重复说明，仍展示各处定位/原文/变更引用，完整候选与复核证据保留在JSON。不新增模型调用，不证明根因事实，不合并不确定/反驳/未完成发现。

## 证据引用编号（0.7.0）

复核阶段的批准行段读取会返回宿主生成的 `receiptId`；模型可用 `{receiptId}` 引用该次读取，避免重新抄写哈希、换行和原文。仍兼容原六字段完整证据。编号仅在本次复核有效，不允许附带字段覆盖证据，不扩展文件权限。宿主解析后仍重新读取批准快照、精确校验并计入共享预算；编号元数据也占用输出额度。报告保留完整证据而非临时编号。无效引用仍明确标记复核未完成，不自动重试，不证明因果或真实审核质量。

## 项目规则（0.5.0）

`code_review_preview` 可传 `rulePaths: ["review-rules.md"]`，只读显式选入的仓库相对路径；不会自动搜索父目录、加载远程规则或执行 include。仅接受 UTF-8 `.md`/`.txt`，最多4个、单个16 KiB、合计32 KiB。规则还占用快照和模型输入预算，超限不静默截断。

规则不能与 `contextPaths` 重复，不能绕过已排除/删除文件；未跟踪规则须同时通过 `selectedPaths` 显式选入变更范围。预览与审批列出路径和SHA-256，并告知全文外发；变更使旧预览失效。初审和复核使用同一规则快照，报告仅列来源/哈希，不重复全文。规则是非可信约束数据，不增加工具或权限；风格违规不自动算缺陷，模型遵循规则的质量尚未实测。

## 大变更覆盖（0.6.0）

预览返回 `plan`：逐文件初始输入字节、关联回退状态和 `ready`/`input-blocked`/`excluded`/`blocked`。预检包括提示词、检索目录、规则及上下文，不外发模型。`minimumCalls` 仅是ready主文件所需初始请求（含窗口批次）的下限，不是费用估算或可完成承诺；检索、复核会增加调用。200文件全ready仍可能被100次全局调用额度截断。

执行报告的 `files`/`coverage` 才是实际覆盖；关联上下文发送不等于作为主文件审查。`initialInputBytes` 仅在进入预检的文件上存在。`followup.suggestedPaths` 列出未完成项（包括初审完成但复核未完成），不自动续审，也不代表阻断原因已解决。再次执行需新预览并由宿主允许工具执行，并显式重选规则/上下文。空建议不代表没有限制或代码正确。

不抬高200文件/4MiB快照及单文件捕获硬限。完整输入超限且检索已批准时，精确hunk可作为保留原始行号的局部窗口，最多20批；只在全部窗口可容纳时启用，单hunk不内部拆分、受限diff不伪造窗口。上下文/规则仍占额度。批次共享每文件超时及全局调用/检索限制，窗口完成账本不代表全文正确，不支持跨审批自动恢复。

## 安装

通过DSH插件管理器安装启用；0.17.0不需要allowModelSending配置。执行权限遵循宿主工具策略，历史开关不再决定注册工具执行。

```sh
dsh plugin add https://github.com/f-e-n-g-0531/dsh-code-review.git
```

本项目不自动修改已有 profile；安装成功也不等于模型与审批链路已验收。

## 使用流程

插件入口由DSH加载器装载；执行将预览快照发送给当前Agent模型，由宿主正常工具权限控制，不重复请求独立审批。

1. 在目标仓库的活跃 Agent 会话中调用 `code_review_preview`。
2. 可用 `selectedPaths` 精确选择变更文件；未跟踪文件必须显式选入。`contextPaths` 提供仓库相对路径的额外上下文。
3. 展示预览中的仓库范围、文件、排除原因及模型提供方。调用 `code_review_execute`，传入 `previewId` 和 `confirmed: true`。
4. DSH 正常工具权限机制决定是否调用执行入口；插件不另发审批请求，不读取never当作授权。执行会把预览快照发送至当前Agent模型，confirmed仅确认预览，不修改宿主权限。
5. 返回 `json`（结构化报告字符串）及 `markdown`（中文报告）。文件、模型或目录变化时需重新预览。

默认在发现的仓库根目录审查，而不是仅当前子目录；预览会显示实际根目录。发送内容包括可审查文件的两侧完整文本、属性和显式上下文，可能包含敏感信息。选择前请检查范围，不要把密钥文件作为上下文。

## 升级后检查

安装版本号不等于当前进程已重新加载。升级后可先调用本地预览：0.6.0应返回 `plan` 和 `rules`（未选择规则时为空数组）。若缺失，核对当前profile的依赖和加载来源，必要时经用户确认重启DSH，再重新预览；不要因此开启外发或重复安装。`ready`仅表示初始输入可容纳，不代表已审查。

## 必要关联上下文（0.8.0）

仅使用批准快照数据，静态相对导入线索记录方向、旧新侧及行号；显式context仍原样作为上下文发送，其关系说明不额外读取或计为审查完成。简单默认/命名别名导入可提示独立调用语法位置（每导入最多20处），可能存在局部遮蔽，不证明绑定、可达性或因果。仅支持保守单行JS/TS语法；动态/包导入、歧义目标、旧路径重命名竞争不猜测，含块注释、模板、续行字符串文件保守跳过。不是完整依赖图，不自动扫描仓库。

## 支持与限制

- Git：HEAD 到工作区净变化，含暂存和未暂存变化；支持未出生 HEAD、重命名、新增和删除。没有独立 staged/unstaged 审查模式。
- SVN：本地每节点 BASE 到工作副本，包含目录属性，无需连接远端。复制、替换、switched、externals、冲突及目录结构变化目前阻断并说明，不宣称完整 SVN 历史支持。
- 二进制、不能解码的内容、链接、非普通文件和超限文件明确阻断。不会转码写回。
- SVN 配置 `svn:keywords` 的文件目前明确阻断，避免把关键字展开误认为代码变化；CRLF/LF 保留原始文本并提示模型不应仅因换行差异报缺陷。
- 当前逐文件审查；模型可在已批准的可审查文件两侧及显式上下文中搜索和读取行段，不访问范围外文件，不开放 shell 或模型工具调用。JS/TS实现与测试可按唯一命名关系及批准变更文件内单行相对静态import/export线索分组，每组最多4个文件，同组两侧作为主文件上下文；仍逐主文件审查，不是一次联合审查或通用依赖图。组输入超预算回退单文件并报告限制；大文件可按精确窗口有界分批；仍超限则不截断，标记未完成。
- v0.2.0 提供有界 diff/hunk 与紧凑编辑引用。发现的归因引用可校验，但因果解释仍未经独立验证；缺失归因保留发现并标记 partial。检索截断同样进入报告限制。
- JSON 报告包含检索来源目录和本地已成功读取的审计元数据，不保存重复源码；retrieved-locally 不表示模型已接收或采用证据。
- 快照双次采集和内容复验用于发现普通并发修改，不是文件系统原子快照，不承诺防御恶意并发链接置换。
- 程序校验定位不等于证明缺陷成立；模型结果需人工判断。`partial` / `failed` / `cancelled` 不表示通过；无发现也不证明代码正确。
- 运行默认最多 200 个变更，单文件 256 KiB，总快照 4 MiB；上下文最多 20 个。单模型输入约 96 KiB，最多 100 次调用，每文件的完整模型/检索循环共用 120 秒超时。开发版每文件的候选生成与复核两阶段各最多 3 轮检索及随后结论调用；全局检索最多 50 次，序列化输出累计 256 KiB，单次最多 64 KiB，读取最多 200 行。取消后等待模型适配器清理完成；适配器必须遵守 AbortSignal，不合作的同进程实现无法强制终止。

## 候选复核（0.4.0）

审批后的候选生成结果会进入证据与反证复核；无候选不追加调用。两阶段共享同一单文件超时、全局模型调用和只读检索预算，复核也不开放可执行工具或扩大快照范围。

报告保留全部候选与原定位，分别显示模型支持、模型反驳、不确定或未完成。支持/反驳必须附带批准快照的来源、SHA-256、完整行范围及精确原文；这些校验不证明缺陷或因果成立。反驳不会静默删除候选；不确定、预算耗尽及无效复核均记入限制。生成阶段的限制在复核超时后仍保留。证据核验的本地读取也消耗共享读取预算。

目前通过受控模型协议和安全回归测试，尚未证明真实模型的误报/漏报改善。真实缺陷评测仍待完成。

## 正式发布

1. 在本仓库 Actions Secrets 中配置 `NPM_AUTOMATION_TOKEN`，需要目标 npm 包的发布权限；工作流仅在 npm 发布步骤映射为 `NODE_AUTH_TOKEN`。
2. 确认包名 `@feng0531/dsh-code-review` 的所有权、版本号和分发许可；更新版本及锁文件，提交并推送同名 `vX.Y.Z` 标签。
3. 在 Actions → CI → Run workflow 选择该标签，设置 `publish: true`。四组测试全部通过后才进入发布任务。
4. 打包一次，在临时目录安装检查，然后先发布 npm，核对 registry 的 SHA-512 完整性，再用同一 tgz 和 SHA256SUMS.txt 创建 GitHub Release。

正式发布只通过 GitHub Actions，不使用本地 npm publish。该流程已在 v0.1.1 完成实际发布及两端同工件核验。若 npm 已成功而后续步骤失败，不要更换同版本安装包或盲目重跑发布；需核对 registry 工件并补齐 GitHub Release。缺少 token、版本不符、安装检查或 npm 发布失败均不会创建 Release。
